# XLines — Android / GitHub Actions

Это Android-проект, не готовый APK. Поддержка Android 8+ (API 26), ARM64 и x86_64.
Приложение: XLines. VLESS + REALITY через libbox v1.14.4,
полный туннель системный туннель Android, импорт QR / xlines:// / файла .xlines,
хранение профиля AES-GCM с ключом Android Keystore, статус и диагностика.
Порты/учётные данные передаются из Windows-клиента, ручная настройка сервера не нужна
после его установки через SSH-мастер. Камера используется только для сканирования QR.
На Android пока нет отдельного SSH-мастера и разделения по сайтам/приложениям.

**Несколько серверов.** Внизу главного экрана панель «название ⌄ · IP · протоколы»: список серверов,
✓ у текущего, «+ Добавить сервер» (QR или файл), «Переименовать», «Удалить». После импорта нового сервера
спрашивается название. Один и тот же сервер (IP + имя) при повторном импорте обновляется, а не дублируется.
Смена сервера — только при выключенном соединении. Старое одиночное хранилище автоматически становится первым сервером.
Настроек обхода и режима владельца на Android нет: клиент просто подключается к тому, что ему выдали. Передаваемые
владельцем сайты обхода и kill switch Android пока не применяет (поля политики в файле игнорируются).

## Сборка APK в GitHub

1. Создайте новый пустой репозиторий. Не загружайте личные файлы .xlines и пароли.
2. Распакуйте ZIP и загрузите СОДЕРЖИМОЕ Android-папки в КОРЕНЬ репозитория:
   app/, .github/, build.gradle.kts, settings.gradle.kts, gradle.properties и остальное.
   Не помещайте всё во вложенную папку, иначе workflow не найдёт проект.
3. Откройте Actions → Build XLines Android → Run workflow.
4. Workflow скачает SDK/NDK, соберёт pinned sing-box libbox и APK, выполнит тесты.
   Сборка ядра может занять десятки минут. Первому запуску нужен интернет.
5. В завершившемся запуске скачайте Artifacts → XLines-Android-debug.
   Распакуйте и установите APK на свой Android, разрешив установку из этого источника.
6. Нажмите «Сканировать QR» или «Импорт файла .xlines».
7. При первом подключении подтвердите системное разрешение туннеля.
8. Для обновлений используйте APK с тем же signing key. Debug-ключ на чистых runners
   может меняться: при конфликте подписи потребуется удалить старое приложение
   и заново импортировать профиль. Для распространения нужен свой стабильный release key.

Workflow НЕ публикует приложение в Google Play и не загружает ключи на сервер.
Он использует contents:read, upload-artifact и не требует SSH/личных секретов.
Поставьте репозиторий private, если не хотите публично показывать изменения приложения.

## Формат обмена

Windows: «Поделиться» → QR-код / Сохранить файл. Android читает тот же XLines v1.
Схема и ограничения описаны в shared/FORMAT.md; тестовый профиль в test/resources
использует адрес 203.0.113.10 и НЕ работает как настоящий доступ.
Код содержит клиентские учётные данные, но не SSH-пароль и не закрытый ключ сервера.
Копия профиля использует тот же доступ. Для другого человека лучше выдать отдельный
доступ через SSH-мастер Windows, чтобы его можно было отозвать независимо.
iOS-приложение не разработано; совместим только запланированный формат, не сам iOS-клиент.


## Что проверено и чего ещё нет

- Единый формат проверен Python-тестами; для JVM добавлены golden-file/URI тесты.
- Kotlin/Compose прошли локальную компиляцию, 4 JVM-теста и lintDebug (без ошибок), с использованием пустого compile-only AAR,
  который исключён из ZIP; это не проверка нативного ядра и не готовый APK.
- Workflow действительно собирает libbox из указанного source commit, а не использует
  compile-only AAR. В проекте нет поддельного .aar и готового работающего APK.
- GitHub workflow, реальное устройство, системное разрешение туннеля, native JNI/Go callbacks,
  TCP/UDP, DNS/IPv6 и восстановление сети ещё требуют реального полного запуска.
- Platform adapter использует reflection для API libbox v1.14.4. Несовпадение API
  выдаст ошибку в диагностике; версия ядра закреплена. Не меняйте её произвольно.
- На Android сначала проверяйте без системной блокировки «без туннеля». После испытаний
  можно отдельно проверить системный постоянное подключение. Собственного kill switch здесь нет.
- Приём/отправка считаются по UID приложения и включают служебный трафик ядра.
